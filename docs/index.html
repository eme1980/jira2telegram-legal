Telegram Bridge for Jira

Jira issue events in your Telegram chats. One bot token, rules per project, no servers of your own.

01What it does

When an issue changes in Jira Cloud, the app posts a message to a Telegram chat you choose. Three events are supported:

  • Issue created — avi:jira:created:issue
  • Issue updated — avi:jira:updated:issue
  • Issue transitioned — avi:jira:issue:transitioned

Notifications go one way only: Jira to Telegram. The app never writes to Jira, and it never reads your Telegram conversations.

If a project has no rule, the event is discarded without calling Telegram at all.

02Before you start

You needWhy
A Jira Cloud site where you are a site administratorThe configuration panel lives in Jira settings, and only admins can install and configure the app.
A Telegram accountTo create the bot and to be in the chat that receives the messages.
A chat for the notificationsA group is the usual choice, so the team reads them together. A private chat with the bot also works.

There is nothing to host, no IP to allowlist and no Jira credential to copy: the app runs on Atlassian Forge.

03Setup in five steps

  1. Create the bot

    Open @BotFather in Telegram, send /newbot, choose a display name and a username ending in bot. BotFather replies with a token that looks like 123456789:AAH….

    Treat that token as a password: anyone who has it can post as your bot.

  2. Put the bot in the chat and find the chat id

    Add the bot to the group (or start a private conversation with it) and send it one message. Then read the chat id from Telegram itself:

    https://api.telegram.org/bot<YOUR_TOKEN>/getUpdates

    Look for the chat.id field in the response. Group and channel ids are negative and usually start with -100; a private chat id is a plain positive number. You can also ask @userinfobot.

    If the chat is a channel, the bot has to be an administrator with permission to post.

  3. Open the panel in Jira

    In Jira, go to Settings (⚙) → Apps → Jira2Telegram Bridge. The panel opens with the token form, your rules and the guide.

  4. Save the token and test the connection

    Paste the bot token and save. Then press Probar conexión: the app calls Telegram's getMe with the token it has stored, so a rejected token surfaces here instead of silently dropping every notification later. The token is stored encrypted in Atlassian's Forge Storage, scoped to your installation, and it is never shown again after saving.

  5. Create a rule and trigger it

    Add a rule: Jira project key, the destination chat id and the events you want. Save, then create or update an issue in that project. The message should arrive within seconds.

The panel is in Spanish. The interface and the notification labels are in Spanish in this version; the Marketplace listing and this documentation are in English. English interface strings are on the roadmap.

04Rules: project, chat, events

A rule maps one Jira project to one Telegram chat and a set of events. Several projects can point to the same chat, so a team can receive all its work in one place.

FieldNotes
Project keyThe short prefix of the issue key, for example DEV in DEV-142. Uppercase.
Chat idNumeric id from step 2. Negative for groups and channels: -1001234567890.
EventsAny combination of created, updated and transitioned.

Rules are validated before they are saved: a malformed token or chat id is rejected with a message instead of being stored. Deleting a rule asks for confirmation and stops the notifications for that project immediately.

05What the messages look like

Every message follows the same shape: an event label, the issue key as a link back to Jira, the summary, the assignee and the current status.

🆕 Issue creado
DEV-142
Login fails on Safari after the last deploy
👤 Miguel Pérez
📍 In progress

The text is sent as Telegram MarkdownV2, so the issue key is clickable and the content cannot break the message formatting.

06Troubleshooting

Nothing arrives

  • Check the rule's project key against a real issue key. A rule for DEV never fires for OPS-7.
  • Press Probar conexión. If it fails, the token is wrong or was revoked in BotFather.
  • Check that the bot is still a member of the chat. If it was removed, Telegram answers with an error and the message is dropped.
  • Remember the app only sends for the events enabled in the rule. A comment on an issue is not one of them.

Telegram says "chat not found"

  • The bot has never been in that chat, or it was removed.
  • The id is wrong: groups need the negative id, and a positive id points to a private chat.
  • The chat is a channel where the bot is not an administrator.

Two messages for the same change

A status change can produce more than one Jira event, and the app sends each enabled event it receives. If you only want one, narrow the rule's event list.

Messages stop after a busy day

Telegram applies rate limits per chat. A project with very high issue volume can hit them; spread the rules across more than one chat if that happens in your team.

07Data and privacy

What the app stores, per installation, in Atlassian's Forge Storage: the Telegram bot token, the destination chat ids and the rules. It does not store issue content, names or email addresses.

The only outbound call goes to api.telegram.org. The message text carries the issue key, the summary, the status and the assignee's display name, because that is what the notification is for.

The full policy is published at https://eme1980.github.io/jira2telegram-legal/.
